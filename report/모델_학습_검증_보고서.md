## 1. 개요

본 제품(AI 기반 작업장 안전관리 시스템)에는 단일 모델이 아니라 **YOLO 계열 경량 검출기 + 자세 추정 + 추적 + 열화상 규칙 분석**을 결합한 Edge 멀티모델 파이프라인이 적합하다. 낙상·통로 위험물·화재/이상 고온이라는 성격이 다른 세 위험을 한 장비(Jetson Orin Nano급)에서 2초 이내에 판단해야 하기 때문이다.

- **입력**: RGB 영상(1080p, RTSP), 열화상 영상·온도 데이터
- **출력**: 위험 수준(Level 0~4), 경광등·부저 제어, 관리자 알림, 이벤트 기록
- **범위**: PRD의 PoC 3종(낙상, 통로 위험물, 화재·고온)에 쓰이는 모델의 선정 근거, 학습 절차, 검증 방법

현재 프로젝트 폴더에는 학습 코드와 실측 결과가 아직 없다. 따라서 이 보고서의 학습·검증 내용은 PoC 수행 계획이며, 결과 수치는 실험 후 채울 칸으로 남겨 둔다.

## 2. 모델 선정

기능별로 "Edge에서 실시간으로 돌아가는가"를 첫 기준으로, "데이터가 적어도 학습 가능한가"를 두 번째 기준으로 후보를 비교했다. 그 결과 모든 기능에서 사전학습 경량 모델을 미세조정하거나 규칙과 결합하는 방식을 택했다.

| 기능 | 후보 모델 | 최종 선정 | 선정 근거 |
| --- | --- | --- | --- |
| 작업자·위험물 검출 | YOLO(n/s), Faster R-CNN, DETR 계열 | **YOLO 계열 nano/small** | 1-stage라 Edge 실시간 추론에 적합, COCO 사전학습에 person·박스류 포함, TensorRT 변환 지원. 2-stage·Transformer 계열은 Orin Nano에서 지연 부담이 큼 |
| 낙상 판단 | 영상 행동인식(3D CNN), 포즈+시계열 분류 | **MediaPipe Pose(또는 YOLO-Pose) + 시계열 분류기(규칙 → 경량 LSTM/1D-CNN)** | 관절 좌표는 배경·조명 변화에 강하고, 낙상 데이터가 적어도 학습 가능. 앉기·눕기와 급낙상을 속도로 구분 |
| 작업자 추적 | DeepSORT, ByteTrack | **ByteTrack** | 외형 임베딩 모델이 필요 없어 가볍고, 낙상 후 무반응·방치시간 측정에 필요한 ID 유지 가능 |
| 화염·연기 감지 | 분류 CNN(MobileNet 등), 검출 모델 | **YOLO 계열 미세조정(fire, smoke 2클래스)** | 위치까지 알려줘야 관리자 알림에 쓸 수 있고, 검출기와 같은 추론 엔진 공유 |
| 이상 고온 | 딥러닝 분류, 임계값 규칙 | **절대온도 임계값 + 온도 상승률(°C/s) 규칙** | 열화상은 온도값 자체가 신호라 학습 없이 설명 가능한 판단 가능 |
| 위험도 판단 | 학습형 분류기, 규칙 엔진 | **규칙 기반 Risk Engine** | Level 0~4 기준이 PRD에 명시돼 있고, 안전 경보는 근거를 설명할 수 있어야 함 |

추론은 전부 Edge(Jetson Orin Nano급)에서 PyTorch → ONNX → TensorRT(FP16)로 변환해 수행한다. 영상이 현장 밖으로 나가지 않고 네트워크 장애 시에도 경보가 동작해야 하기 때문이다(별도 보고서의 엣지 vs 클라우드 검토와 같은 논리).

## 3. 데이터

실제 사고 영상은 구하기 어렵기 때문에 **공개 데이터셋으로 사전학습 → 연출 촬영·현장 영상으로 미세조정**하는 2단계로 구성한다. 실제 화재는 만들지 않고 공개 영상과 안전하게 만든 온도 데이터만 쓴다.

| 기능 | 공개 데이터(후보) | 자체 수집 | 라벨 형태 |
| --- | --- | --- | --- |
| 작업자·위험물 검출 | COCO(person 등) | 통로에 박스·공구·자재를 놓고 웹캠 촬영 | 바운딩 박스 |
| 낙상 | UR Fall Detection, Le2i Fall 등 낙상 영상 | 매트 위 연출 낙상 + 앉기·눕기·굽히기 등 정상 행동 | 구간 단위 이벤트 태그(fall / normal) |
| 화염·연기 | D-Fire 등 공개 화재·연기 데이터셋 | 화재 오탐 유발 장면(조명, 반사광, 주황 조끼) | 바운딩 박스 |
| 이상 고온 | — | 헤어드라이어·냄비 등으로 안전하게 만든 온도 상승 로그 | 시간별 온도 + 이벤트 여부 |

**전처리**(현장조사 체크리스트 기준)

- 얼굴 비식별화를 라벨링 전 단계에 수행
- 입력 해상도 640px 리사이즈·정규화, 명암 차가 큰 현장은 CLAHE 적용
- 통로 ROI 밖 영역 마스킹으로 연산량과 오탐 감소
- 증강: 밝기·대비, 모션 블러, 가림(Random Erasing), Mosaic, 원근·스케일 변환
- 하드 네거티브: 마네킹·포스터 속 사람, 주황 조명, 반사 조끼를 별도 수집
- 분할: 학습 70% / 검증 15% / 테스트 15%. 같은 영상에서 나온 프레임이 서로 다른 세트에 섞이지 않도록 **영상(촬영 세션) 단위로 분할**

## 4. 학습 방법

학습은 전이학습(Transfer Learning) 기반 미세조정으로, PC GPU에서 학습하고 Edge로 변환·배포하는 순서로 진행한다.

1. **검출기 미세조정**: COCO 사전학습 YOLO nano/small을 클래스 person, box, tool, material, fire, smoke로 미세조정. 초기에는 백본을 고정(freeze)해 적은 데이터에서의 과적합을 막고, 검증 성능이 멈추면 전체를 풀어 낮은 학습률로 재학습
2. **낙상 분류기 학습**: 포즈 모델로 프레임별 관절 좌표를 추출하고, 1–2초 윈도우의 특징(골반 높이 변화 속도, 몸통 기울기, 바운딩 박스 가로/세로 비)을 만든다. 먼저 규칙으로 기준선을 잡고, 데이터가 쌓이면 LSTM/1D-CNN으로 대체
3. **클래스 불균형 대응**: 낙상·화재는 희귀 이벤트이므로 오버샘플링, 클래스 가중치 또는 Focal Loss 적용
4. **임계값 조정**: "놓치면 안 되는" 위험이므로 검증 세트에서 Recall ≥ 95%를 먼저 만족하는 confidence 임계값을 고르고, 그 안에서 오탐률을 최소화
5. **Edge 변환**: PyTorch → ONNX → TensorRT FP16, 정확도 저하가 1%p 이내인지 확인 후 배포
6. **지속 개선**: 관리자가 대시보드에서 "오탐"으로 분류한 이벤트를 하드 네거티브로 모아 주기적으로 재학습

| 하이퍼파라미터(검출기 초기값) | 값 |
| --- | --- |
| 입력 크기 | 640 × 640 |
| Epoch | 100 (검증 mAP 20 epoch 정체 시 조기 종료) |
| Batch | 16 |
| Optimizer / 초기 학습률 | SGD, 0.01 (cosine decay) |
| 증강 | Mosaic, HSV, Flip, Random Erasing, Motion Blur |
| 학습 환경 | PyTorch, 로컬 GPU 또는 Colab |
| 추론 환경 | Jetson Orin Nano급, TensorRT FP16 |

## 5. 검증 방법과 결과

검증은 세 단계로 나눈다: ① 테스트 세트에서의 모델 성능, ② 학습에 쓰지 않은 새 연출 영상으로 하는 시나리오 시험, ③ Edge 장비에서 재는 지연시간. 합격 기준은 PRD의 PoC KPI다.

| 항목 | 지표 | 측정 방법 | PoC 목표 | 결과 |
| --- | --- | --- | --- | --- |
| 작업자 검출 | mAP@0.5, Recall | 테스트 세트 | 사람 검출 ≥ 97% | 측정 예정 |
| 낙상 감지 | Recall, 오탐률 | 연출 낙상 vs 앉기·눕기 등 정상 행동, 혼동행렬 | Recall ≥ 90%, 오탐 ≤ 5% | 측정 예정 |
| 통로 위험물 | 검출률, 방치시간 오차 | ROI에 박스를 N초 두고 스톱워치와 비교 | ≥ 90%, ±1초 | 측정 예정 |
| 화재·고온 | Recall, 오탐률 | 공개 화재 영상 + 생성 온도 로그, 조명·반사광 하드 네거티브 | Recall ≥ 90% | 측정 예정 |
| 판단 지연 | 이벤트 → 판단(초) | 이벤트 발생 프레임과 판단 로그의 타임스탬프 차 | 낙상 ≤ 2초, 화재 ≤ 3초 | 측정 예정 |
| 추론 속도 | FPS (Edge) | TensorRT FP16, 카메라 동시 입력 | ≥ 15 FPS(가정) | 측정 예정 |

**검증 원칙**

- 테스트 세트는 임계값 조정에 쓰지 않고 마지막에 한 번만 평가한다.
- 정확도만 보지 않고 Recall(미탐)과 오탐률을 따로 보고한다. 희귀 이벤트에서는 정확도가 높아도 낙상을 놓칠 수 있기 때문이다.
- 주간·야간, 근거리·원거리, 가림 유무로 나눠 조건별 성능을 함께 기록해 약한 조건을 찾는다.
- 최종 시연에서 SAFE / FALL DETECTED / OBSTACLE WARNING / FIRE·HIGH TEMP WARNING 네 상황과 부저·경광등 동작을 확인한다.

## 6. 결론 및 향후 과제
