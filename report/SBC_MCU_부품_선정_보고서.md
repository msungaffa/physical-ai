# SBC·MCU 부품 선정 보고서

- 작성자: 박민성
- 작성일: 2026-10-16
- 대상 제품: AI 기반 작업장 안전관리 시스템 (PRD v1.0)

---

## 1. 요약

| 구분 | 선정 | 한 줄 이유 |
|---|---|---|
| SBC (판단) | **NVIDIA Jetson Orin Nano Super 8GB** | 카메라 4채널 디코딩과 모델 3개 동시 추론을 2초 안에 처리할 수 있는 유일한 후보 |
| MCU (경보 구동) | **ESP32-DevKitC (ESP32-WROOM-32E)** | Wi-Fi MQTT와 UART 예비 경로를 함께 쓰고, 값이 싸고, 하트비트 워치독을 구현하기 쉬움 |

SBC가 AI 판단을 맡고, MCU는 경광등·부저를 직접 켜고 끄는 역할을 따로 맡는다. 이렇게 나누면 SBC가 멈춰도 MCU가 하트비트 끊김을 감지해 "시스템 이상" 경보를 낼 수 있다. PRD에 적힌 "ESP32 또는 STM32" 중 ESP32를 기본으로 정하고, STM32는 무선을 쓸 수 없는 현장의 대안으로 둔다.

---

## 2. SBC와 MCU를 왜 둘 다 쓰나

| 항목 | SBC (Jetson) | MCU (ESP32) |
|---|---|---|
| 하는 일 | 영상 수신, AI 추론, 위험 Level 판단 | 경보 명령 수신, 릴레이 구동, 하트비트 감시 |
| 운영체제 | Linux + Docker | 없음 (펌웨어 하나만 실행) |
| 부팅 시간 | 수십 초 | 1초 이내 |
| 멈출 가능성 | 상대적으로 높음 (메모리 부족, OS 업데이트, 프로세스 오류) | 낮음 (단순한 루프 하나) |
| 멈췄을 때 | MCU가 감지해 황색등 | 하드웨어 워치독이 MCU를 스스로 재시작 |

경보 출력을 Jetson GPIO에 직접 연결하지 않은 이유도 여기에 있다. 판단 장치가 멈추면 경보 장치까지 함께 멈추는 구조를 피하기 위해서다. 또 Jetson 40핀 GPIO는 3.3V 로직이라, 24V 경광등을 제어하려면 어차피 중간에 릴레이가 필요하다.

## 3. SBC 선정

### 3.1 요구 조건

| 항목 | 조건 | 근거 |
|---|---|---|
| 입력 | 장비 1대당 RGB 1080p 3채널 + 열화상 1채널 (RTSP) | PRD ROI 가정: RGB 6대, 열화상 2대, Edge 2대 |
| 모델 | YOLOE + Pose + ByteTrack + 열 분석 동시 실행 | 모델 학습·검증 보고서 |
| 지연 | 위험 판단 2초 이내, 현장 경고 3초 이내 | PRD 성공 지표 |
| 배포 | PyTorch → ONNX → TensorRT FP16 | 모델 학습·검증 보고서, 추론 엔진 비교 |
| 네트워크 | 인터넷 없이도 판단·경보 가능 | 엣지 vs 클라우드 검토 |
| 비용 | 8개월 투자비 회수 계획 안에 들어갈 것 | PRD ROI |

### 3.2 후보 비교

| 후보 | AI 성능 | 장점 | 이 제품에서의 한계 |
|---|---|---|---|
| **Jetson Orin Nano Super 8GB** | 67 TOPS (GPU) | 하드웨어 디코더(NVDEC), TensorRT, DeepStream 지원. 기존 변환 흐름 그대로 사용 | 개발 키트 약 $249. 8GB를 CPU·GPU가 공유해 메모리 관리 필요 |
| Raspberry Pi 5 + AI HAT+ (Hailo-8) | 26 TOPS (NPU) | 저렴하고 자료가 많음 | YOLOE처럼 클래스를 바꾸는 모델은 Hailo 변환이 어려움. 4채널 디코딩에 CPU 부담 큼 |
| RK3588 보드 (Orange Pi 5 Plus 등) | 6 TOPS (NPU) | 가격 대비 성능 좋음, 하드웨어 디코더 있음 | RKNN 변환이 까다롭고 모델 3개 동시 실행에 여유 부족 |
| Jetson Orin NX 16GB | 100 TOPS 이상 | 메모리·성능 여유 | 가격이 높아 ROI(8개월 회수)에 불리 |

### 3.3 결론

- **현장 배포용**: Jetson Orin Nano Super 8GB. 실제 공장 설치 시에는 같은 모듈을 쓴 **팬리스 산업용 캐리어 보드**가 먼지·진동에 강하다.
- **PoC 시연용**: Raspberry Pi 5도 가능하다. 단 USB 웹캠 1대, 낙상 감지 1종처럼 범위를 줄인 경우에 한한다.
- Jetson 내부 소프트웨어 배치는 `Edge_SBC_컨테이너_구조_보고서.md`에 정리했다.

## 4. MCU 선정

### 4.1 요구 조건

| 항목 | 조건 | 이유 |
|---|---|---|
| 통신 (주) | Wi-Fi로 MQTT 구독 | 제어함을 경광등 근처에 두고 Jetson과 선 없이 연결 |
| 통신 (예비) | UART (USB-시리얼) | 브로커나 Wi-Fi가 멈춰도 경보 명령 전달 |
| 출력 | GPIO 4채널 이상 (적색·황색·부저·예비) | 절연형 릴레이 모듈 구동 |
| 입력 | ADC 1채널 (선택) | MQ-2 연기 센서 보조 입력 |
| 안전 | 하드웨어 워치독, 하트비트 타임아웃 처리 | Jetson 멈춤 감지, MCU 자체 멈춤 시 재시작 |
| 비용 | 제어함 2개분, 저렴할 것 | ROI |
| 개발 | MQTT 라이브러리와 자료가 많을 것 | 과제 기간 안에 펌웨어 완성 |

### 4.2 후보 비교

| 후보 | 코어 | 무선 | 로직 전압 | 장점 | 이 제품에서의 한계 |
|---|---|---|---|---|---|
| **ESP32-DevKitC (WROOM-32E)** | 듀얼코어 240MHz | Wi-Fi + BT 내장 | 3.3V | 값이 쌈(보드 약 1만 원 안팎). Arduino·ESP-IDF의 MQTT 예제가 풍부. 하드웨어 워치독 내장 | 공장 Wi-Fi가 불안정하면 끊길 수 있음 → UART 예비 경로로 보완. ADC 정확도가 낮음 |
| STM32 Nucleo-F446RE | Cortex-M4 180MHz | 없음 | 3.3V | 실시간성·장기 안정성 좋음. 독립 워치독(IWDG), CAN 지원 | 무선이 없어 Jetson과 반드시 유선 연결. MQTT를 쓰려면 별도 네트워크 모듈 필요 |
| Arduino Uno R4 WiFi | Renesas RA4M1 48MHz (+ ESP32-S3 통신 칩) | Wi-Fi 내장 | 5V | 5V 로직이라 일부 5V 모듈 연결이 쉬움. 교육 자료 많음 | 칩이 둘이라 구조가 복잡하고 ESP32보다 비쌈. 성능 대비 이점 적음 |
| Raspberry Pi Pico W (RP2040) | 듀얼코어 Cortex-M0+ 133MHz | Wi-Fi 내장 | 3.3V | 매우 저렴. MicroPython으로 빠르게 개발 | MQTT·산업용 사례가 ESP32보다 적음 |

### 4.3 결론

**ESP32-DevKitC를 선정한다.**

1. **Wi-Fi MQTT와 UART를 한 보드에서 모두 쓸 수 있다.** 주 경로(MQTT)와 예비 경로(UART)를 동시에 열어 둘 수 있다.
2. **하트비트 워치독을 구현하기 쉽다.** `hb/edge`를 N초 동안 받지 못하면 황색등을 켜는 로직은 타이머 하나로 충분하다. MCU가 스스로 멈추면 내장 하드웨어 워치독이 재시작시킨다.
3. **값이 싸고 자료가 많다.** 제어함 2개분이라 가격 차이가 크지 않지만, 개발 기간을 줄이는 효과가 크다.
4. **3.3V 로직이 Jetson과 같다.** UART 직결 시 레벨 변환이 필요 없다. 릴레이는 포토커플러 절연형(JD-VCC 분리형)을 써서 3.3V로도 안정적으로 구동한다.

**STM32로 바꾸는 조건**: 현장에서 무선 사용이 금지되거나 Wi-Fi가 매우 불안정한 경우, 또는 PLC·CAN 연동이 필요한 경우다. 이때는 Jetson과 UART/USB(또는 RS-485)로만 연결한다. 무선을 쓸 수 없지만 펌웨어를 그대로 쓰고 싶다면 **유선 이더넷 포트가 있는 ESP32 보드**(PoE 지원 제품 포함)도 대안이 된다.

### 4.4 MCU 펌웨어 안전 설계

| 항목 | 설계 |
|---|---|
| 부팅 직후 | 모든 릴레이 OFF로 시작 (오경보 방지) |
| 경보 명령 | `alarm/cmd`(MQTT) 또는 UART로 Level·장치 ID 수신 → 해당 릴레이 ON |
| Jetson 하트비트 | `hb/edge`가 N초 동안 없으면 황색등 ON (N은 실측 후 결정) |
| MCU 자체 멈춤 | 하드웨어 워치독이 재시작 |
| 연기 센서 (선택) | MQ-2 값이 기준을 넘으면 Jetson에 보고. 단독으로는 경보를 내지 않음 (오경보 방지) |

## 5. 선정 부품 사양 요약

| 부품 | 모델 | 수량 | 전원 | 통신 |
|---|---|---|---|---|
| SBC | Jetson Orin Nano Super Developer Kit 8GB | 2 | DC 9–19V, 25W 모드 | GbE, USB 3.2, 40핀 GPIO·UART (3.3V) |

| 릴레이 | 4채널 5V 절연형 (SRD-05VDC-SL-C) | 2 | 코일 5V, 채널당 71.4mA | GPIO 입력 |

전압·전류·전력 예산의 자세한 값은 `하드웨어_부품_사양_보고서.md`를 따른다.
