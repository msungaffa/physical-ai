How it works

보고, 판단하고, 움직입니다

모든 분석은 현장의 소형 AI 장비에서 처리합니다. 빠르고, 영상이 밖으로 나가지 않습니다.

  1. 감지

    일반 카메라와 열화상 카메라가 작업장을 24시간 지켜봅니다.

    • 사람·물체·불꽃 찾기
    • 작업자 자세 읽기
    • 설비 온도 측정

  2. 판단

    한 장면이 아니라 몇 초의 흐름을 보고 위험도를 5단계로 매깁니다.

    • 앉은 건지, 넘어진 건지
    • 지나가는 건지, 방치된 건지
    • 조명인지, 불인지

  3. 행동

    경광등과 부저가 즉시 울리고, 관리자 휴대폰으로 위치와 사진이 갑니다.

    • 경광등·부저 작동
    • 관리자 실시간 알림
    • 사건 자동 기록

관리자가 알림을 정상 · 오경보 · 사고로 표시할수록 AI는 그 현장에 맞게 더 정확해집니다.

Risk levels

위험한 만큼만 울립니다

다섯 단계로 나눠, 단계마다 다르게 대응합니다.

  • Level 0정상 작업정상
  • Level 1통로에 물체가 잠깐 나타남관찰
  • Level 2통로에 물체가 오래 방치됨주의 · 대시보드 경고 → 관리자 알림
  • Level 3작업자 낙상 의심위험 · 경광등·부저 + 위치·영상 전송
  • Level 4불꽃과 고온 동시 감지긴급 · 현장 경보 + 긴급 알림

경광등과 부저는 현장에서 직접 제어합니다. 인터넷이 끊겨도 울립니다.

Features

주요 기능

  • 낙상 감지MEDIAPIPE POSE

    앉은 것과 쓰러진 것을 구분합니다. 쓰러진 뒤 움직임이 없으면 즉시 위험 단계로 올립니다.

  • 통로 장애물 감지YOLOE + 추적

    관리자가 화면에 통로를 그리면, 그 안에 물체가 얼마나 오래 있는지 잽니다. 지나가는 것과 방치된 것을 구분합니다.

  • 화재·과열 감지YOLOE + 열화상

    영상 속 불꽃·연기와 열화상 온도를 함께 봅니다. 둘 다 이상할 때 긴급 경보를 울려 오경보를 줄입니다.

  • 현장 경고와 알림ALERT

    경광등·부저가 울리고, 위험 종류·위치·사진이 관리자에게 바로 전달됩니다.

  • 관리자 대시보드DASHBOARD

    카메라, 경보, 온도, 처리 이력을 한 화면에서 봅니다. 사고가 반복되는 구역도 찾아냅니다.

판단은 왜 Jetson Orin Nano인가요

보드 (SBC)AI 성능장점이 제품에서 걸리는 점
Jetson Orin Nano Super 8GB67 TOPS (GPU)영상 디코딩 하드웨어(NVDEC)와 TensorRT를 갖춰, 기존 PyTorch → ONNX → TensorRT 흐름을 그대로 씁니다.8GB를 CPU와 GPU가 함께 써서 메모리 제한(mem_limit)을 둡니다.
Raspberry Pi 5 + AI HAT+26 TOPS (Hailo-8 NPU)저렴하고 자료가 많습니다.클래스를 바꿔 쓰는 YOLOE는 Hailo 변환이 어렵고, 4채널 디코딩에 CPU 부담이 큽니다.
RK3588 보드6 TOPS (NPU)가격 대비 성능이 좋고 하드웨어 디코더가 있습니다.RKNN 변환이 까다롭고, 모델 3개를 동시에 돌리기엔 여유가 적습니다.
Jetson Orin NX 16GB100 TOPS 이상메모리와 성능에 여유가 큽니다.가격이 높아 8개월 투자비 회수 계획에 불리합니다.

※ PoC 시연(웹캠 1대, 낙상 감지 1종)은 Raspberry Pi 5로도 가능합니다. 현장 설치에는 같은 Orin Nano 모듈을 쓴 팬리스 산업용 캐리어 보드를 씁니다.

경보는 왜 ESP32가 따로 맡나요

경광등을 Jetson에 바로 연결하면, Jetson이 멈출 때 경보도 같이 멈춥니다. 그래서 펌웨어 하나만 도는 MCU가 경보를 맡고 Jetson이 살아 있는지도 지켜봅니다. 1초 안에 부팅되고, 스스로 멈추면 하드웨어 워치독이 다시 켭니다.

MCU무선 · 로직장점이 제품에서 걸리는 점
ESP32-DevKitCWi-Fi 내장 · 3.3VWi-Fi MQTT와 UART 예비 경로를 함께 씁니다. 값이 싸고 MQTT 예제가 많으며, Jetson과 로직 전압이 같습니다.공장 Wi-Fi가 불안정하면 끊길 수 있어 UART 예비 경로로 보완합니다.

Data pipeline

카메라 영상이 경보가 되기까지,
데이터를 두 번 다듬습니다

AI 앞에서는 영상을 깨끗하게 정리하고(전처리), AI 뒤에서는 순간적인 착각을 걸러냅니다(후처리). 그래서 어두운 창고에서도 정확하고, 괜한 경보가 줄어듭니다.

전처리

모델이 보기 전에, 영상을 일정한 품질로 맞춥니다.

  1. 프레임 샘플링

    필요한 프레임만 골라 장비 부담을 줄입니다.

    예시 설정 30fps → 10fps
    낙상위험물화재

  2. 왜곡 보정과 영상 겹치기

    렌즈 휘어짐을 펴고, 열화상을 일반 영상 위에 정확히 겹칩니다.

    예시 설정 체커보드 캘리브레이션 + 호모그래피
    낙상위험물화재

  3. 저조도·역광 보정

    어두운 구석과 역광 속에서도 작업자 윤곽을 살립니다.

    예시 설정 CLAHE, clipLimit 2.0, 8×8
    낙상위험물

  4. 온도 변환과 노이즈 제거

    센서 값을 섭씨로 바꾸고, 순간 튀는 값을 걸러냅니다.

    예시 설정 5프레임 중앙값 필터
    화재

  5. 관심 구역만 보기

    지정한 통로·설비만 보고, 컨베이어처럼 늘 움직이는 곳은 뺍니다.

    예시 설정 카메라별 다각형 마스크
    위험물화재

  6. 크기 맞춤과 정규화

    AI가 받는 크기와 형식으로 맞춥니다.

    예시 설정 640×640 letterbox, FP16
    낙상위험물화재

후처리

모델이 본 결과를, 믿을 수 있는 판단으로 바꿉니다.

  1. 신뢰도 기준과 중복 제거

    확신 낮은 검출은 버리고, 겹친 박스는 하나로 합칩니다.

    예시 설정 confidence 0.4, NMS IoU 0.5
    낙상위험물화재

  2. 객체 추적

    같은 사람·물체에 계속 같은 번호를 붙여 시간을 따라갑니다.

    예시 설정 ByteTrack, 30프레임 유지
    낙상위험물

  3. 자세 특징 계산

    떨리는 관절 좌표를 다듬고, 몸이 기우는 각도와 속도를 잽니다.

    예시 설정 One Euro 필터, 몸통 각도 > 60°
    낙상

  4. 시간 창 판정

    한 장면이 아니라 몇 초의 결과를 모아 판단합니다.

    예시 설정 최근 15프레임 중 10프레임 이상
    낙상위험물화재

  5. 영상 + 온도 복합 판단

    같은 자리에 불꽃과 고온이 함께 있을 때만 긴급 경보를 울립니다.

    예시 설정 화염 AND (온도 > 80℃ 또는 +5℃/분)
    화재

  6. 경보 안정화

    경보가 깜빡이거나 같은 알림이 반복되지 않게 합니다.

    예시 설정 켜짐 0.6 / 꺼짐 0.4, 재알림 60초
    낙상위험물화재

후처리를 켜면, 앉는 동작은 무시하고 실제 낙상만 남습니다

학습 방법

공개 데이터로 기초를 다지고, 직접 찍은 현장 영상으로 다듬습니다. 영상 단위로 학습 70 / 검증 15 / 테스트 15로 나눕니다.

  1. 자동 라벨링

    SAM 3가 현장 영상 속 박스·공구·자재를 자동으로 표시하고, 사람은 검수만 합니다.

  2. 검출기 미세조정

    YOLOE를 사람·박스·공구·자재·불꽃·연기에 맞춰 다듬습니다. 640×640, 100 epoch.

  3. 낙상 분류기

    골반 높이 변화와 몸통 기울기 규칙으로 시작하고, 데이터가 쌓이면 LSTM으로 바꿉니다.

  4. 드문 사건 보강

    낙상·화재 데이터는 적어서 오버샘플링과 Focal Loss로 보강합니다.

  5. 기준값 조정

    놓치지 않는 것(Recall)을 먼저 맞추고, 그다음 오경보를 줄입니다.

  6. 현장 장비 변환

    TensorRT FP16으로 변환하고, 정확도 손실이 1%p 이내인지 확인합니다.

우리 제품의 선택

ONNX Runtime현장 장비(Jetson)에서는 TensorRT 가속

  • 가장 고르게 빠릅니다느린 쪽 5%도 68 ms. 경보가 늦어지는 순간이 가장 적습니다.
  • 정확도 손해가 없습니다네 엔진 모두 mAP50 0.6250으로 같습니다.
  • Jetson GPU로 바로 이어집니다같은 ONNX 파일을 TensorRT 실행기로 돌리면 됩니다.
PyTorch 학습→ONNX 변환→ONNX Runtime 검증→Jetson TensorRT FP16

    ※ AMD Ryzen 5 7530U 노트북 CPU, 6스레드, FP32, 640×640 기준 실측입니다. Jetson 실측은 PoC에서 진행합니다.

    • OpenVINO중앙값은 57 ms로 가장 빠르지만, 느릴 때 100 ms까지 튑니다. Intel 장비라면 다시 볼 후보입니다.
    • NCNN · TFLiteARM 모바일용 엔진이라 이 PC에서는 1.6~2배 느렸습니다. 라즈베리파이로 바꾸면 다시 잽니다.
    • 용량모두 약 9.5 MB(FP32)입니다. FP16으로 바꾸면 절반 가까이 줄어듭니다.
